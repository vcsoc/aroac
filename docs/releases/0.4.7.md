# AROAC 0.4.7 — Linux x86-64 and macOS ARM64 desktop release

- Map base layer is now a **Satellite / Topographic** segmented toggle immediately left of **Flat map / Globe**, available independently of the Range panel. Resetting range assumptions does not alter the base layer; the chosen layer remains a local preference.
- Home and selected-location cards display Open-Meteo model-grid elevation above sea level, sea-level and local barometric pressure, and calculated standard-atmosphere pressure altitude when data is available. These are estimates, not surveyed heights or a calibrated instrument reading.
- Link planning shows estimated ground elevations for both endpoints, including on routes too long for terrain profiling. For paths from 50 m to 500 km, an on-demand 33-point Open-Meteo DEM sample estimates 4/3-Earth terrain clearance using the entered antenna heights; responses are locally cached for offline reuse. The point spacing, stale-data status and limitations are shown. Samples can miss obstructions, buildings, vegetation, Fresnel-zone clearance and unusual refraction; **a positive result does not verify a usable radio link**.
- A collapsible planning panel provides source and destination setup guidance and, when the local repeater directory is available, shortlists nearby candidate shared repeaters with listed output frequency, offset, mode and distances. Missing tones and settings are explicitly left unassigned; verify current repeater details, access and local licence/band rules before transmitting.
- Group the grey-line and clock-follow toggles, move Appearance help beside related labels, and display **AROAC** in place of a legacy heading in the sources editor. Internal `oar` data paths, identifiers and protocol names remain for compatibility.
- New desktop profiles default to persistent sign-in **only if secure OS secret storage is available**. Explicit opt-outs are respected; unencrypted tokens still require express consent on machines without secure storage. No password is saved.

The executable remains all-in-one and local-first, owning its SQLite database and application logic. No separate server, browser installation, remote account or configured server address is required. Optional relay transport remains an unaudited preview; online maps/weather/terrain/directory downloads contact their respective data providers.

## Download and verify

Download from [GitHub Releases · v0.4.7](https://github.com/vcsoc/aroac/releases/tag/v0.4.7):

- `AROAC-0.4.7.AppImage` — standalone Linux x86-64 desktop application; use `APPIMAGE_EXTRACT_AND_RUN=1` where FUSE is unavailable.
- `aroac-0.4.7.tar.gz` — Linux x86-64 archive; does not self-update.
- `AROAC-0.4.7-SHA256SUMS.txt` — place beside both downloads and run `sha256sum -c AROAC-0.4.7-SHA256SUMS.txt`.
- `latest-linux.yml` — AppImage update metadata containing SHA-512 integrity and size.

On macOS Apple Silicon, download `AROAC-0.4.7-arm64.dmg` or `AROAC-0.4.7-arm64-mac.zip` and `AROAC-0.4.7-macOS-arm64-SHA256SUMS.txt`. Run `shasum -a 256 -c AROAC-0.4.7-macOS-arm64-SHA256SUMS.txt` alongside the DMG, ZIP and their two `.blockmap` files, or verify the downloaded package's checksum entry individually. `latest-mac.yml` contains updater metadata; a live macOS update was not tested.

The binaries exceed GitHub's normal Git-file size limit: they are attached to the GitHub Release, **not committed as Git blobs**. Both checksum manifests are committed in `releases/`. Checksums establish download integrity, not independent publisher identity; these packages are unsigned.

## Tested platforms and limits

Built on Linux x86-64 with Electron/Node. All **76** Node tests and **19** browser tests passed. The packaged AppImage passed standalone local-first desktop, sign-in/persistence, map interaction and link-planning UI smoke tests. The archive was built and its checksum verified, but was not launched independently. A live upgrade from a previously published version was not exercised for this release. DEM/service logic was unit-tested with mocked provider data; a sample online elevation request succeeded on the build host, but terrain findings are not field-verified.

The macOS ARM64 DMG and ZIP were built with Electron/Node on macOS ARM64. On macOS, 72 Node tests passed and 4 Linux-only tests were skipped. The packaged application passed standalone local-first desktop, guidance/tutorial, workspace, sign-in/persistence, map interactions, link-planning UI, account/profile/device and map-selection smoke tests. ZIP/DMG integrity and local SHA-256 checks passed. The release-ten smoke test still fails on the known macOS `/private/var` versus `/var` temporary-path comparison. Neither installer UI nor a live in-place update was tested. The macOS application is not Developer ID signed or notarized, so Gatekeeper may block it. Windows binaries were not built or tested for 0.4.7. iOS requires macOS/Xcode for compilation and signing, and its local database implementation remains incomplete. Android remains blocked pending a genuinely JDK-free local engine/UI port and physical-device testing. The rejected legacy Capacitor scaffold is not a release. Android 16/API 36 remains the minimum product target, not a verified compatibility claim. No Java, JDK or .NET tooling was used.
